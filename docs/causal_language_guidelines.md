# DriftGuard-X Causal Language Guidelines

This document outlines the strict wording constraints for the UI, reports, and documentation generated by the DriftGuard-X intervention engine.

## Core Principle
**Do not claim absolute causal proof, safety certification, or statistical confidence beyond what is deterministically implemented and measured.** Exhaustive replay is a comparison oracle for scheduler efficiency; it is not a claim of absolute causal truth in the wild.

## Allowed vs. Forbidden Phrasing

### 1. Root Cause Attribution
* **Forbidden**: "The root cause is definitively X." "X provably caused the failure." "Absolute causal proof."
* **Allowed**: "A likely recoverable root cause has been identified." "X is a likely root cause based on exhaustive replay." "Recoverable contribution."

### 2. Intervention Efficacy
* **Forbidden**: "This intervention guarantees a 10% improvement." "Applying this will fix the issue entirely."
* **Allowed**: "During exhaustive replay, this intervention produced a mean reliability improvement of +10%." "Strong correlative improvement during replay."

### 3. Abstention & Uncertainty
* **Forbidden**: "The system failed to find the issue." "No root cause exists."
* **Allowed**: "Insufficient evidence to confidently recommend an intervention." "No candidate produced a material, policy-relevant improvement above the threshold."

## UI Disclaimer Requirements
Every Root Cause Report and Intervention Planner view MUST include a prominent disclaimer block noting the epistemic limits of the diagnostic process.

**Required Disclaimer Elements:**
1. *Learned attribution only.*
2. *Does not imply causal proof beyond exhaustive replay bounds.*
3. *Notes on constrained repeated trials (e.g., Cost constraints limited repeated trials to N=3).*

## Tie-Breaking and Partial Evidence
Ties and uncertainty must be represented directly in the ranked candidate list. Do not force a unique root cause when the aggregate scores are statistically indistinguishable. Report variance and $N$ trials alongside the mean improvement to explicitly model uncertainty.
